# 1080p: the res1062 sites with 1920x1080 (0x780 x 0x438), as 1.0.0's res1080 set, the ladder's docked entries included,
# so the scene stays at 1920x1080 whatever scale the dynamic-resolution logic picks. Each ladder level picks one size
# when the scene target has the docked width and another when it has not; handheld (1280x720 targets, main+0x40d5a0)
# always takes the second. Those two handheld entries (40f1a4 and 40f1b0) get res1062's 1280x720, the handheld targets'
# own size: 1920x1080 there is larger than the targets the game made for handheld, the level's target is never
# created, and loading a save in handheld read through its null texture in main+0x9d0df0 (issues #25 and #38).
# Level 2's docked width is w19, which the function sets to the handheld 1280 before the ladder (main+0x40f128, also the
# width of a 1280x720 target it makes there, so left alone): with the height raised to 1080 that level was 1280x1080,
# and AC_SSAA=1440p made it 1707x1440, which lost the device on an RTX 5070 Ti (issue #51). 40f1d8 takes the scene
# target's width (w0) instead, as level 0 does, so the level is 1920x1080 docked and keeps 800x720 in handheld.
# res1062 gets the same site.
# 1920x1080 is the engine's maximum (on

# Field of view (AC_FOV, runtime/resolution.c res_fov_live). A camera's lens (*(camera+0x58)) keeps the vertical view
# angle at +0x27c (radians: 50 degrees in play, the shot's own in cutscenes), the aspect ratio at +0x278 and near / far
# at +0x270 / +0x274. While the lens is dirty (+0x28c), main+0x9a3010 loads those four and builds the projection
# matrix at lens+0x40 (bl main+0x9b28e0); main+0x9a3054 builds the same for a second target. The scene setup also
# copies the angle into the render scene at +0x140 for its screen-size work (two copies of that sequence). Each site
# multiplies the loaded or stored angle by the factor on page +60 (rt_fov_s0), so the projection, the culling built
# from it and the screen sizes stay in step; while the game's cutscene flag is set the angle passes unscaled, so
# cutscenes keep their framing. Off while AC_FOV is 100, so the camera code is the game's own.

# Dynamic frame rate for the 60 fps mode (the menu's AC_FPS: 30 = shipping 30 fps, 60 = 60 fps with the fix).
# The game's frame timer (main+0x91DBB0) clamps its step to [1, 2] frames of 1/30 s, so at 60 fps everything runs at
# twice its speed. The set replaces the timer's step with the frame's real time (runtime/frame_rate.c rt_fps_timer,
# which also keeps the whole 30 fps ticks the steps add up to), and fixes what counts frames instead of reading the
# step: every input/action/hitstop/rumble frame counter is scaled by the whole ticks so its window lasts wall-clock time
